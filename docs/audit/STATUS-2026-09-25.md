## 1. Wie hier gemessen wird — zwei Achsen, nicht eine

Der Auftrag verlangt, **Erfüllungsgrad** von **Nachweisstufe** zu trennen. Ein
bestandener Komponententest *kann* mit offener Produktintegration zusammenfallen.
Darum steht jede ID auf zwei Achsen:

| Nachweisstufe | Bedeutung |
|---|---|
| **N0 — behauptet** | nur Text/Plan, keine Messung |
| **N1 — im Code** | Datei und Struktur vorhanden, kein Lauf |
| **N2 — Komponententest** | ein gezielter Testlauf bestanden (Unit/Integration, isolierte Umgebung) |
| **N3 — Projektcheck** | im Gesamtzusammenhang geprüft, weiterhin isoliert |
| **N4 — Host-Live** | am echten Fedora-Desktop / echten Browser / echtem Programm gemessen |
| **NB — blockiert** | Nachweis durch externe Voraussetzung gesperrt, Grund benannt |

Wichtig und bewusst so formuliert: **N2 ist nicht N4.** Fast alle unten als
„getestet" geführten IDs stehen auf N2/N3. Das ist kein Mangel an Sorgfalt,
sondern die ehrliche Grenze dessen, was eine Testumgebung belegt.

Erfüllungsgrad (wie bisher): `getestet`, `teilweise`, `implementiert-unbestätigt`, `fehlt`, `extern-blockiert`.
