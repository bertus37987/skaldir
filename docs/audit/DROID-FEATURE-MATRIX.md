# DROID-FEATURE-MATRIX — Anforderung → Codepfad → Nachweis

**Stand:** 2026-10-16 · Repo `/home/willy/Agentic_Projects/Skaldir_Agent` · HEAD `0b693d9`
(Abnahme M1–M6 abgeschlossen; siehe [DROID-ACCEPTANCE.md](DROID-ACCEPTANCE.md) und [DROID-TAKEOVER.md](DROID-TAKEOVER.md)).

**Zweck:** jede Pflicht-ID des Masterplans genau einmal, mit produktivem Einstieg, Registrierung,
Dispatcher, Executor, Ergebnisoberfläche, Verifikation, Tests und Restlücke. Statuswerte gibt es
nur in dieser Schreibweise:

| Status | Bedeutung |
|---|---|
| `implementiert-und-integriert` | Codepfad existiert **und** ist vom produktiven Einstieg aus erreichbar **und** hat einen Test |
| `live-verifiziert` | zusätzlich existiert ein echter Live-Beleg (Kommando + Exitcode + Artefakt) |
| `teilweise` | existiert, aber nicht (voll) in den produktiven Pfad verdrahtet, oder nur als Engine |
| `fehlt` | kein Codepfad gefunden |
| `extern-blockiert` | konkrete äußere Blockade benannt (nicht als Host-Defekt behauptet) |

**Belegdisziplin (bindend):** Klasse, CLI-Verb oder grüner Unit-Test sind **keine** Fähigkeit.
Ein Fixture-/PTY-/Container-Ergebnis ist **kein** Host-Live-Ergebnis. Jede Zeile nennt
`datei:zeile`, wie sie heute im Arbeitsbaum steht; fehlt ein Beleg, steht dort `kein Beleg`.
Alte Berichte (`docs/audit/STATUS-2026-09-25.md`, `IMPLEMENTATION-AUDIT.md`,
`COMPUTER-USE-GUI-E2E.md`, `PLATFORM-MATRIX.md`) wurden als **Hinweis** gelesen und gegen den
aktuellen Code geprüft; wo sie widersprechen, gilt der Code.

**Spaltenkürzel** (in allen Tabellen gleich):

| Kürzel | Spalte |
|---|---|
| PE | Produktiver Einstieg (wie der Nutzer/es die Fähigkeit auslöst) |
| REG | Registrierung / Schema (wo Fähigkeit und Vertrag deklariert sind) |
| DISP | Dispatcher (wer den Aufruf annimmt und rafft) |
| EXE | Executor (wer die Wirkung ausführt) |
| RES | Ergebnisoberfläche (was der Nutzer sieht) |
| VER | Verifikation (wie das Ergebnis geprüft wird) |
| TEST | Tests (Datei-/Testname) |
| GAP | Restlücke / aufgelöster Widerspruch |

Die vier Prüfungen liegen auch als Manifest-Kommandos bereit
(`services.yaml` → `audit-id-rows`, `audit-id-dups`, `audit-status-counts`,

Zeichen der Tabellenspalte muss im regulären Ausdruck entwertet sein (`\|`), sonst matcht `^|` als
leere Alternative und jeder Zeile.
